# DSH Memory Pro v0.3.1

这版补齐删除会话后的派生索引回收，以及在途写入保护。

- 检索/原文回读前核对宿主活、冷会话清单，回收已删除来源的 chunks、向量和增量游标。
- 清理与写入共享每会话删除代数；嵌入等待期间来源被删除，旧任务即使恢复也不能提交回来。独立进程的旧快照同样受到保护。
- schema 2 → 3 增量升级，保留正常索引；原有事实、固定记忆、自定义数据库路径和快捷键 ID 不变。

## 安装或升级

```sh
dsh plugin --profile web add https://github.com/QIANLING-0831/dsh-memory-pro/releases/download/v0.3.1/dsh-memory-bundle-0.3.1.tgz
```

把 `web` 换成你实际使用的 profile。升级时在原 profile 执行同一条命令，随后重启 DSH 并刷新页面；共享同一派生库的所有进程都应升级并重启。无需删库、重新保存记忆或逐个安装内部插件。安装包与 `SHA256SUMS` 一同提供。

宿主目前没有独立删除通知：停机期间删除的会话，会在下一次检索/回读时清理。来源列表读取失败不会被当作空库。原始会话文件与派生 SQLite 不是跨存储原子事务；详细边界见 [删除回收说明](https://github.com/QIANLING-0831/dsh-memory-pro/blob/v0.3.1/docs/DELETED-SESSION-INDEX.md)。

## 验证与兼容

- 152 项自动测试、8/8 包检查通过；安装包测试确认包含七个内部插件及删除保护实现。
- Linux / Node 24.21.0 / DSH 0.2.0-rc.2，实际安装包通过官方 CLI 全新安装、完整 Web profile 启动和冷重启检查。
- 从真实 v0.3.0 包安装旧数据，再通过官方 CLI 换装 v0.3.1；独立进程重启后验证 schema 2 → 3、旧残留回收、在途写入拒绝、原文引用、正常历史、事实/固定记忆和自定义路径保留。
- 发布流程先验证构建产物的安装与升级，再上传 Release 资产。详见 [安装升级验收与复跑](https://github.com/QIANLING-0831/dsh-memory-pro/blob/v0.3.1/docs/RELEASE-UPGRADE-VERIFICATION.md)。

需要 Node.js 24、pnpm 和兼容宿主，DSH 声明范围仍为 `>=0.1.5-rc.3 <0.3.0`；插件 v0.3.1 与宿主版本号独立。本次未重跑在线模型，也未验证原生 Windows/macOS 桌面壳或大历史库性能。此前跨会话续聊在线结果与范围见 [在线验收记录](https://github.com/QIANLING-0831/dsh-memory-pro/blob/v0.3.1/docs/ONLINE-RECALL-EVAL.md)。
