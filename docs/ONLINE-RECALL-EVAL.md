# 在线模型跨会话续聊验收

## 测什么

新模型会话只收到一条自然语言请求，不能看到旧讨论或预期答案。可用工具来自真实挂载的 DSH 插件：当前会话检索、同工作区搜索、原文回读。通过测试专用 stdio MCP 桥接，将生产工具的名称、描述、参数 schema 和执行结果原样交给在线模型，不另写检索实现。

测试关闭模型客户端的 shell、图片和 Web 搜索，忽略用户配置/规则，并以临时空目录和简短的中性系统提示启动，不加载本仓库文件或复用先前模型会话。模型自行决定是否调用工具；用户请求没有工具名或来源 ID。测试夹具、答案和判定器在模型不可读的父目录/运行进程中。

DSH 侧使用独立的 SessionStore、SystemPrompt、Tools、JSONL/zstd Persistence、CJK SessionQuery 和 MemorySearch。旧会话先写盘，销毁 writer 后再启动 reader，新 caller 是真实 SessionStore 创建的空会话。仅使用合成数据；不读取日常 DSH_HOME，不复制登录凭据。

## 判定

每次同时满足：

1. 模型主动调用 `memory_search_workspace`，而非凭空回答。
2. 模型调用 `memory_read`，实际回读包含后续纠正的窗口。
3. 最终回答采用新的决定和关键约束。
4. 最终回答引用纠正那条消息的真实 `source_id`。
5. 工具返回和最终回答都不含其他工作区的私有标记。

三个场景：Redis 草案改为 SQLite 离线运行；监听端口从 7311 改为仅 `127.0.0.1:8647`；普通日志从 30 天改为 7 天且排障包豁免。每个场景重复三次，失败即停，不通过重抽样挑成功结果。

固定事实、引用和实际工具调用由确定性断言判断；对最终回答是否明确遵守纠正及后续安排另作人工阅读复核。这里不使用另一个模型作为 judge，也不以强制工具调用代替自主检索。

## 复跑

先按 [离线宿主验证](WORKSPACE-RECALL.md) 安装隔离 runtime，并在本机完成 Codex CLI 登录：

```sh
node scripts/eval-workspace-recall.mjs "$PWD/.dsh-verify/workspace-host" "$PWD/.dsh-verify/online-recall" 3
```

默认在线模型固定为 `gpt-6.1-sol`，可用 `RECALL_EVAL_MODEL` 显式更换。脚本不会自动切换模型或回退供应商。输出目录包含每次的模型事件、回答、工具调用和 summary；临时会话库路径也记录在结果中，便于排查。输出都是合成数据，位于 gitignored 的 `.dsh-verify` 下；运行结束后可自行清理记录的临时目录。

## 范围

这是“在线模型 → MCP 测试桥 → 原样 DSH 工具/真实存储”的工具选择、证据回读和续聊验证。不是完整 DSH AgentLoop/Web UI/原生桌面端的在线验收。默认嵌入仍是项目已有的 char-overlap，能检查调用链和中文字符检索，不能代表生产语义嵌入的质量。

三类合成任务的小样本通过不等于任意模型、任意问法或大语料库的可靠性保证。完整结果及模型/客户端版本见相邻的 `workspace-recall-online-2026-11-14.json`。
