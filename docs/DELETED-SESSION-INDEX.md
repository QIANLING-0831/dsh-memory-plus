# 删除来源的索引回收与写入屏障

v0.3.1 安装包已包含此修复；v0.3.0 Release 不包含。安装/升级命令见根 README，升级后应重启所有共享派生库的 DSH 进程。

此前在途索引可先读快照、等待嵌入；如果期间会话被删除，恢复后仍会写回 chunks、向量与游标。现在清理与写入共用 SQLite 的短写事务和每会话代数，旧代数不能提交。

## 行为

- 当前会话搜索、工作区搜索、原文回读前，按宿主 `sessionQuery.listSessions()` 的完整活/冷清单回收已消失来源；也可显式调用 `ctx.memorySearch.pruneDeletedSessions(signal?)`。
- 清理原子删除 chunks、vec 与增量游标，并保留仅含 ID、代数、删除标记的屏障。已回收的记录不会在每次检索时反复改写。
- 索引在嵌入前登记代数；嵌入后确认来源仍存在且 header 匹配，在写锁内再检查代数。即使另一进程还持有旧来源视图，已提交的清理也能阻止其在途写入。
- 同 ID 的新会话可以重新索引；旧写入无法覆盖删除后重建的数据。来源变更时工作区搜索返回 partial，避免沿用失效的索引快照。
- 失败的清单读取不等于空清单；可列出但不可读的来源不是删除。`session/disposed` 只是卸载，持久化历史仍保留。
- schema 2 → 3 为增量升级，不重建正常历史的 chunks/vec。

## 边界

宿主没有独立删除通知，因此离线删除在下次检索/回读或显式清理时回收；后台没有轮询计时器。原始会话存储与 SQLite 是两个存储，不能承诺文件系统删除与派生库提交的原子性：最终来源检查后发生的外部删除，由下一轮核对回收。屏障保证的是清理提交后，使用此实现、在清理前登记的写者不能恢复旧索引。共享派生库须对应同一逻辑会话库，所有写者须升级；旧实现不遵守屏障。这里只回收派生索引行，不是磁盘安全擦除功能。

## 验证（2026-11-14）

Linux / Node 24.21.0，真实 `node:sqlite` 和 sqlite-vec：

- 全量自动测试 152/152，8/8 包检查通过；本地主分支开发包通过官方 CLI 单包安装及完整 Web profile 的首次启动、冷重启、检索/回读/隔离与核心记忆回归。该本地构建没有上传或覆盖 v0.3.0 Release。
- 自动回归覆盖旧残留回收、首次索引及增量索引的嵌入等待期删除、独立进程的旧快照与同 ID 重建竞争、来源头变更、清单读取失败、清理中途回滚、schema 2 升级，以及过期清单不删除新索引。
- 负例探针移除提交时的代数校验后，独立进程回归失败；恢复原实现后同一用例通过，证明测试确实约束删除屏障。
- 工作区回归检查删除后的数据库行已清除，嵌入期间迁移工作区会明确报告 unavailable；向量候选隔离用例仍实际索引 100 条其他工作区消息。
- `verify-deleted-session-index.mjs` 挂载发布的 DSH 0.2.0-rc.2 services 与真实 JSONL/zstd 持久化，调用注册的检索/回读工具：在嵌入暂停时删除合成历史，验证旧写入拒绝、三类索引行回收、引用失效；停机期间再删除另一会话，重启后的首次检索清理残留，正常冷历史仍可检索，SQLite `quick_check` 为 `ok`。

